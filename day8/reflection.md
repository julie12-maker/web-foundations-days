# Reflection

## Most difficult concept
The most difficult concept for me was APIs and databases. With APIs, it was hard to understand that a request can reach the server successfully and still fail, for example a 404 response, so I had to check the status code myself instead of assuming success. With databases, it was hard to see how data spread across several tables fits together, especially joins and the join table that links students to courses.   to overcome it I tested the fetch error path by breaking the URL on purpose, and I ran each SQL query on its own in the playground and compared the result with the data I had inserted, until the results made sense.

## What I would improve
Based on the feedback I received, I would improve my API design work by expanding docs/api-design.md to specify six production endpoints for the real QuickNotes API. Each endpoint would have a clear path, an example payload, and a standardized JSON error response body, so every error looks the same and the front end can handle it in one place. This would make the API easier to build, test and use.
